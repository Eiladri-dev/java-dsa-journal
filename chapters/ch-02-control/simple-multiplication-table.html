01 Program objective

Print the first ten multiples of N

The programme reads one integer and writes N × 1 through N × 10. The same ten lines are written three times, and before each block the multiplier is set back to 1 so the count starts from the same place.

purpose

Read N from the keyboard, then print N times k are N*k for k running from 1 to 10 — once for each of the three blocks in the file.

Negative input is rejected by one test; every accepted value produces ten lines per block.

inputs

  • one integer token, read by sc.nextInt();
  • no check on the type of what was typed;
  • no upper or lower bound beyond the int range;
  • the prompt uses print, so the value typed sits on the same line as it;
  • a negative value ends the programme after one message;
  • sc.close() runs after the last block.

behaviour

One prompt, one read, then a fixed sequence: three headings, each followed by ten product lines. The row count never changes with the input.

For a negative number the output is a single line and nothing else. For 0 the ten lines are all 0 times k are 0.

run order one read, one guard, three blocks of ten lines

Scanner sc = new Scanner(System.in) print "Enter your number : " // print, so the cursor stays on this line int N = sc.nextInt() // the token typed after the prompt if (N < 0) → one message, nothing else else 1. mul = 1; while (mul < 11) → 10 lines 2. for (mul = 1; mul <= 10; mul++) → 10 lines 3. mul = 1; do { … } while (mul <= 10) → 10 lines sc.close()

The three blocks print the same ten strings. The counter mul is declared once, before the first block, and is reused by the other two.

02 Problem statement

The task, stated without the code

For an integer N, the multiplication table is the list of products N × 1, N × 2 … N × 10, one per line, each line naming the number, the multiplier and the product. Negative input must be reported rather than tabulated.

04 Key Java concepts

        
The machinery inside the file

        
Nine parts of the file, each described as it appears: what the statement does with this input, and what state it leaves behind.

      


      

        

          
print vs println

          
The prompt uses print, so no newline is written and the number typed appears after the colon on the same line. The first heading opens with \n, which supplies the newline the prompt did not.

        


        

          
while

          
while (mul < 11) — tested before each pass. The counter is raised inside the body, so the loop ends when it reaches 11.

        


        

          
for

          
for (mul = 1; mul <= 10; mul++)

          
No type is written in the header: mul already exists, so this statement assigns it rather than declaring a new variable. Initialisation, test and update sit in one line.

        


        

          
do-while

          
The body prints and increments, then while (mul <= 10) is evaluated. The first pass cannot be skipped, which is why mul is set to 1 with a separate statement before it.

        


        

          
one counter, reused

          
int mul is declared once, above the first block. Both later blocks restore it to 1 — by the for initialiser, and by an assignment before the do.

        


        

          
int arithmetic

          
N * mul multiplies two int values, so the product is computed in 32 bits before it is turned into text. A product outside that range wraps and the wrapped value is what gets printed.

        


        

          
concatenation

          
N + " times " + mul + " are " + (N * mul)

          
Left to right, the first + joins a number to a string, and every later operand is joined the same way. * binds tighter than +, so the product is computed before it is joined; the parentheses make that grouping visible.

        


        

          
guard clause

          
if (N < 0) prints one message and leaves the else block untouched. The programme then ends; it does not ask for another number.

        


        

          
Scanner

          
sc.nextInt() reads one integer token and throws InputMismatchException if the token is not an integer — an exception the file does not catch. sc.close() follows the last block.

Limits, stated as facts

          
    
            
  • The product is computed in 32 bits. N * mul is an int multiplication; the largest N whose tenth multiple still fits is 214 748 364.
    • 
            
  • Overflow is not detected. No comparison follows the multiplication, so a wrapped value is printed in exactly the same format as a correct one.
    • 
            
  • The row count never varies. Ten rows per block for every accepted input, including 0 — the bounds are constants in the file.
    • 
            
  • No retry. A negative value ends the programme; it does not ask for another number.
    • 
            
  • Type errors end the programme. A letter at the prompt raises InputMismatchException, which is not caught.
    • 
            
  • The prompt does not end its line. print is used rather than println, so the newline before the first heading is supplied by the heading itself.
    • 
            
  • The table is written three times. The same ten strings are produced by three separate blocks; the file has no method that prints a table once.
    • 
          

        


        

          
Correctness, stated carefully

          
For −2 147 483 648 ≤ N < 0: one message, no table. That is the behaviour the guard specifies.

          
For 0 ≤ N ≤ 214 748 364: every product is inside the int range, so all ten lines per block carry the exact mathematical product, and the three blocks print identical rows.

          
For N above that: individual lines still print, but some products are no longer the mathematical ones. Because all three blocks compute N * mul the same way, they all print the same wrapped values — the repetition is consistent, not correct.

09 Time & space complexity

        
Thirty rows, whatever the input

        
Every block is bounded by constants written into the file, so the work does not depend on the value read. Only the width of the numbers inside the lines changes.

      


      

        

          
Time — Θ(1)

          
Ten passes in the first block, ten in the second, ten in the third: thirty print statements and thirty multiplications for any accepted input. The three blocks run one after another, not nested, so the cost is added rather than multiplied.

          
The loop bounds are literals (11 and 10), so no input can lengthen the table.

10 Takeaways & future connections

        
What the run establishes

      


      

        

          
output thirty identical rows

          
For every accepted input the three blocks write the same ten lines, because the strings, the bounds and the arithmetic are the same. The only visible difference is the heading above each group.

        


        

          
bound the literal sets the length

          
11 and 10 are the only things that decide how many rows appear. The input cannot change the count, and no value of N makes the table shorter or longer.

        


        

          
range the product sets the limit

          
N * mul is an int multiplication. Up to 214 748 364 the tenth multiple still fits; beyond that the row prints a wrapped value in the same format as a correct one.

        

      


      

        

          
If the counter were not reset

          
After the first block mul is 11, because that is the value that failed the test. The for header sets it back to 1 in its own initialiser; the do-while needs the separate mul = 1; line above it. Remove that line and the body would run once with mul = 11, print N times 11, increment to 12 and stop — one row instead of ten, and a row the other blocks never print.

        


        

          
Why the parentheses matter

          
"… are " + (N * mul) multiplies first, then converts the product to text. Multiplication binds tighter than +, so the brackets only make the order visible: "…" + N * mul would parse the same way. Written the other way round — "…" + N + mul — the digits would be joined as text instead of multiplied, and the row would read 7 times 3 are 73.

        

      


      

        
next

        
The three blocks differ only in where the test sits and how the counter is written. A method that takes the number and the row count would produce the table once, and the for header would carry both bounds as parameters.

        
The other thread is the product's type. Widening it moves the point where the printed value stops matching the arithmetic; the decision of how many rows to offer, and of what to do with input that is too large, sit next to that choice rather than inside the loop.

// 2 : Write a program to print the multiplication table of a number N, entered by the user.
import java.util.*;

public class multiply {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        System.out.print("Enter your number : ");
        int N = sc.nextInt();

        if (N < 0)
            System.out.println("Multiplication table does not exist for negative numbers!");

        else {

            System.out.println("\n...Calculating the multiplication table of " + N + " by using while loop");
            int mul = 1;
            while (mul < 11) {
                System.out.print(N + " times " + mul + " are " + (N * mul) + "\n");
                mul++;
            }

            System.out.println("\n...Calculating the multiplication table of " + N + " by using for loop");
            for (mul = 1; mul <= 10; mul++) {
                System.out.print(N + " times " + mul + " are " + (N * mul) + "\n");
            }

            System.out.println("\n...Calculating the multiplication table of " + N + " by using do-while loop");
            mul = 1;
            do {
                System.out.print(N + " times " + mul + " are " + (N * mul) + "\n");
                mul++;
            } while (mul <= 10);
        }
        sc.close();
    }
}

Where this could go next

        
The programme writes a ten-row table three times and stops at whatever int can hold. The open questions are how many rows belong in a table, and what should happen when a product leaves the type.

      


      

        

          
The row count as a value

          
Ten is written into the file three times, as 11 and 10. Making it a variable or a parameter lets the same code print five rows or fifty, and removes the difference between the two comparisons at the same time.

    for (int k = 1; k <= rows; k++) {
        System.out.println(n + " times " + k + " are " + (n * k));
    }
}

          
One call writes the table once. What has to be decided first is whether three separate copies of the output are wanted at all — for N = 7 the console currently shows the same ten lines three times.

          
Not assumed. Whether that is the next program you write is your call — the page stops at the question rather than choosing a destination for you.

        


        

          
A product that does not wrap

          
Every printed value is an int multiplication. A wider type moves the boundary; an arbitrary-precision type removes it.

          
long product = (long) n * k;
System.out.println(n + " times " + k + " are " + product);

          
One cast is enough to make every row exact for any int input, because the largest product is about 2.1 × 10¹⁰ and a long holds up to 9.2 × 10¹⁸. Nothing else in the block changes: the same counter, the same bounds, a product that stays correct.
