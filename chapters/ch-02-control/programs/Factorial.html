01 Program objective

Compute n! from one integer

The programme reads one integer, settles the negative case with a single test, and then prints the factorial of that value three times. Every printed figure comes from the same product, recalculated from the same starting point.

purpose

Read num from the keyboard and print its factorial, three times over, with the value of num repeated in every message the programme writes.

Negative numbers are excluded by a single guard. Every accepted value is computed without a range check.

inputs

  • one integer token, read by sc.nextInt();
  • no validation of the type, and no upper bound;
  • a negative value ends the programme after one message;
  • the accumulator is long, so results stay exact up to 20!;
  • three calculations, each starting from fac = 1 and n = num;
  • sc.close() releases the stream at the end.

behaviour

One prompt, one read. From there the output is a fixed sequence: three headings, each followed by its result line.

For a negative number the output is a single line and nothing else. For 0 the three lines all print 1, and the last of them is printed by a branch that runs instead of its loop.

run order one read, one guard, three independent calculations

Scanner sc = new Scanner(System.in) print "Enter your number : " // println, so the cursor moves to the next line read num, then copy it into n if (n < 0) → one message, nothing else else 1. fac = 1 while (n > 0) { fac *= n; n--; } 2. fac = 1; n = num for (i = n; i > 0; i--) { fac *= i; } 3. fac = 1; n = num if (n == 0) print 1 else do { fac *= n; n--; } while (n > 0)

The first loop leaves n at 0, so the second and third sections begin by restoring it from num. The multiplication itself is the same in all three: the accumulator is multiplied by the current counter and the counter is reduced by one.

02 Problem statement

The task, stated without the code

For a non-negative integer n, the factorial is the product of every integer from 1 to n, with 0! defined as 1. The programme must compute that product with three different loop forms and print each result on its own line. Negative input must be reported rather than computed.

Inputs, outputs and the guard

inputwhat happensresult printed
n < 0the guard is taken, no loop runsone message
n = 0while and for do no work; do-while takes its own branch1, 1, 1
n ≥ 1three calculations, n iterations eachn! three times

The definition used. n! = n × (n − 1) × … × 2 × 1, and 0! = 1 by definition. Because the accumulator starts at 1 and the loop stops before reaching 0, the empty product for n = 0 is already correct in the first two loops.

Why the zero case has its own branch. A do-while body always runs at least once. With n = 0 that single pass would multiply by zero and print 0 instead of 1, so the programme tests n == 0 before entering the loop and prints the accumulator unchanged.

03 Core logic & approach

        
From the keyboard to three printed values

        
One guard, then three blocks that each restore the accumulator and the counter before multiplying. The restores matter because the first block consumes the counter on its way down to zero.

The blocks differ in where the test sits: before the first pass in the first two, after it in the third. For every positive input the pass count is therefore the same, and only 0 sends them down different paths.

        

      


      

        

          
terms descending order

          
The blocks multiply n, then n − 1, then n − 2, down to 1. Multiplication is commutative, so ascending order would give the same product; the file happens to use descending in each case.

          
5 × 4 × 3 × 2 × 1
20 → 60 → 120 → 120 → 120

        

        

          
count n passes each

          
For n ≥ 1 each block multiplies exactly n times. For n = 0 the first two run zero times and the third is bypassed, so the total is 3n multiplications for positive input and 0 for zero input.

          
n = 5  →  15 multiplications
n = 0  →   0 multiplications

        

        

          
guard one condition

          
Only one input condition is tested: n < 0. There is no upper bound, no retry loop and no check on the type of the input, so the range of accepted values is decided by int and by what Scanner can parse.

        

      

    

  


  
  

    

      

        
04 Key Java concepts

        
The machinery inside the file

        
Nine parts of the file, each described as it appears: what the statement does with this input, and what state it leaves behind.

      


      

        

          
accumulator

          
long fac = 1; then fac = fac * n; inside the loop — a running product, updated once per pass.

          
A start of 0 would make every product 0; 1 is the identity for multiplication, so the empty product at n = 0 is already correct.

        


        

          
while

          
while (n > 0) { fac *= n; n--; } — the test is at the top, so the body runs only while the counter is positive.

          
The number of passes is the value that was read, and n is the variable the test reads — after this block it is 0.

        


        

          
for

          
for (int i = n; i > 0; i--) {
    fac = fac * i;
}

          
Initialisation, test and update are written in one line, and i exists only inside the loop.

          
The counter is a new variable, so n keeps its value across this block: afterwards i is 0 and n is still the number that was read.

        


        

          
do-while

          
The body runs once, then while (n > 0) decides whether it runs again. The test is at the bottom, so the first pass is unconditional.

          
Because the first pass cannot be skipped, 0 is written as its own case: if (n == 0) prints the accumulator without entering the loop.

        


        

          
long arithmetic

          
fac is a long while n is an int. In fac * n the int is widened to long before the multiplication, so the product is evaluated in 64 bits.

          
13! already exceeds the int range, so the accumulator is a long: the product is exact up to 20! and wraps beyond it.

        


        

          
state reset

          
Before the second and third calculations the programme writes fac = 1 and n = num. Both are required: the first loop consumed n down to 0.

          
Without the n = num line the later blocks would start from 0, fail their tests at once and print 1.

        


        

          
Scanner

          
sc.nextInt() reads the next integer token. The prompt uses println, so the value appears on the line after it, and sc.close() releases the stream at the end.

          
One integer is read. nextInt() throws InputMismatchException if the next token is not an integer, and that exception is not caught.

        


        

          
guard clause

          
if (n < 0) prints one message and leaves the else block untouched. There is no retry, so the programme ends after the message.

          
The factorial is undefined for negative integers in this definition, so the value is reported rather than computed — and the programme does not ask for another number.

        


        

          
prompts and headings

          
Each calculation is introduced by a line beginning with \n, which puts a blank line before it. The number appears in the heading as well as in the result, so the output can be read without the input.

          
Three results follow one another, so each line names the number and the loop that produced it.

The boundaries of what this programme accepts

Limits, stated as facts

          
    
            
  • The exact range ends at 20. 20! = 2 432 902 008 176 640 000, which is below 2⁶³ − 1 = 9 223 372 036 854 775 807. 21! = 51 090 942 171 709 440 000, which is larger, so the stored value wraps to −4 249 290 049 419 214 848 and that is what all three result lines print.
    • 
            
  • Overflow is not detected. The programme has no comparison after the multiplication, so a wrong result is printed in exactly the same format as a correct one.
    • 
            
  • No upper bound on input. Any int is accepted. A large positive value produces three long loops, each running n times, with a wrapped result.
    • 
            
  • No retry. A negative value ends the calculation; the programme does not ask for another number. This is a single guard, not a validation loop.
    • 
            
  • Type errors end the programme. A letter at the prompt raises InputMismatchException, which is not caught.
    • 
            
  • Prompt text ends with a space. println("Enter your number : ") writes the space and then a newline, so the value typed appears on the following line.
    • 
            
  • Three calculations, one input. The same value is computed three times; the programme has no way to compute one factorial and print it once.
    • 
          

        


        

          
Correctness, stated carefully

          
For 0 ≤ n ≤ 20: correct. Each block computes the product of the integers from n down to 1 with an accumulator that starts at 1, so the empty product at n = 0 is 1 and every positive value matches the mathematical definition.

          
For n > 20: the arithmetic no longer represents n!. Multiplication past the 64-bit limit wraps, and because each of the three blocks multiplies in the same order with the same type, all three print the same wrapped value. The programme does not report this.

          
For n < 0: the specified message is printed and nothing else. The guard uses the working copy n, which equals num at that point, so the condition is the one that was intended.

09 Time & space complexity

        
Linear in the number, three times over

        
Each loop performs exactly n multiplications for positive n, so the programme performs 3n of them in total. Memory is a fixed set of variables regardless of the value read.

      


      

        

          
Time — O(n)

          
The while loop runs n times, the for loop runs n times, and the do-while loop runs n times for n ≥ 1. Each pass does one multiplication and one decrement, so the total work is proportional to n, with a constant factor of three.

          
The loops run one after another, not nested, so the cost is added rather than multiplied. There is no inner loop anywhere in the programme.

Space — Θ(1)

          
Three variables are live during a calculation: num, n and the accumulator fac, plus the loop counter i inside the for statement. None of them grows with the input, and nothing is stored for later use.

          
No array, list or string holds the terms, so a larger n costs more time but exactly the same memory.

10 Takeaways & future connections

        
What the run establishes

      


      

        

          
output the three figures agree

          
For every accepted input the three printed values are identical, because the factors, their order and the arithmetic type are the same in each block. The value does not depend on which block produced it.

        


        

          
zero one input changes the path

          
0 is the only value where the blocks behave differently: the first two perform no passes, and the third prints its accumulator from the branch written for it. The printed line is the same 1 either way.

        


        

          
range the accumulator sets the limit

          
A long holds 20! exactly and nothing larger; an int would have stopped at 12!. The declaration, not the loop, decides how far the result stays exact.

        

      


      

                

          
If the second reset were missing

          
After the first block the counter is 0, because it was decremented once per pass. Reset only fac and the second block would initialise its counter from that 0, fail its test at once and print 1; the third would then find n still 0, take the n == 0 branch and also print 1. The output would read 120, 1, 1 — both assignments are required for the three results to agree.

        


        

          
Why 21! prints as a negative number

          
The blocks multiply the same factors in the same order into a long, so they pass through the same intermediate values and overflow in the same place. 21! needs 66 bits; the stored pattern has its top bit set and is read as −4 249 290 049 419 214 848, which is 21! − 2⁶⁴. The digits printed are the wrapped residue, not a decimal error.

        

      




        
next

        
The multiplication is identical in all three blocks and only the header changes. A single routine taking the start value and returning the product would remove the repetition and print the value once.

        
The other thread is the accumulator's type. Moving to a wider type, or to a representation that grows as needed, extends the range of inputs that keep an exact result; deciding when to stop accepting input also belongs to the same decision, and that is a different problem from writing the loop.

            factorial.java
            
          

          
//1 : Write a program to find the factorial of any number entered by the user
import java.util.*;

public class factorial {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        System.out.println("Enter your number : ");
        int num = sc.nextInt();
        int n = num;

        if (n < 0)
            System.out.println("Factorial does not exist for negative numbers!");
        else {
            System.out.println("\n...Calculating the factorial of " + num + " by using while loop");
            long fac = 1;
            while (n > 0) {
                fac = fac * n;
                n--;
            }
            System.out.println("The factorial of " + num + " using while loop is " + fac);

            System.out.println("\n...Calculating the factorial of " + num + " by using for loop");
            fac = 1;
            n = num;
            for (int i = n; i > 0; i--) {
                fac = fac * i;
            }
            System.out.println("The factorial of " + num + " using for loop is " + fac);

            System.out.println("\n...Calculating the factorial of " + num + " by using do-while loop");
            n = num;
            fac = 1;
            if (n == 0)
                System.out.println("The factorial of " + num + " using do-while loop is " + fac);
            else {
                do {
                    fac = fac * n;
                    n--;
                } while (n > 0);
                System.out.println("The factorial of " + num + " using do-while loop is " + fac);
            }
        }
        sc.close();
    }
}

12 Next step

        
Where this could go next

        
The program answers its question for 0 ≤ n ≤ 20 and prints that answer three times. The open questions are what happens past that range, and how the three copies of the same calculation might become one.

      


      

        

          
One calculation instead of three

          
The three blocks share a body: multiply the accumulator by the counter, then move the counter. A method that takes the start value and returns the product removes the repetition, and what is left is one calculation and one printed value.

          
static long factorial(int k) {
    long fac = 1;
    for (int i = k; i > 1; i--) {
        fac = fac * i;
    }
    return fac;
}

          
With that method the three sections become one read, one check and one printed line. What has to be decided first is whether three separate prints are wanted at all — for n = 5 the output currently shows the same 120 three times, which is the visible consequence of computing it three times.

          
Not assumed. Whether that is the next program you write is your call — the page stops at the question rather than choosing a destination for you.

        


        

          
A range that does not wrap

          
The accumulator decides where the result stops being exact. A wider fixed type moves that boundary; an arbitrary-precision type removes it, at the cost of a different kind of multiplication.

          
import java.math.BigInteger;

BigInteger fac = BigInteger.ONE;
for (int i = 2; i <= num; i++) {
    fac = fac.multiply(BigInteger.valueOf(i));
}
System.out.println(fac);      // exact for every int

          
Nothing else in the programme changes: the same loop, the same counter, a value that grows instead of wrapping. Deciding when to accept an input at all, and how many digits the answer will have, are separate questions from writing the loop.
