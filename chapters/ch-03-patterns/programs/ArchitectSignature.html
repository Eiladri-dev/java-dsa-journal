01 Program objective

Print three initials as block letters

Draw the letters E, K and D side by side in a fixed grid of five rows and seventeen columns, then print a banner with the name and the initials. The shape of every cell is decided by the column that owns it — and by a second test that describes that letter.

purpose

Produce a fixed piece of text art: a signature. Five rows are printed, each row exactly 32 characters wide, so the three letters hold their vertical alignment.

The programme reads nothing. Every number it needs — the row count, the letter width, the middle row, the position of the K's arms — is written into the source, so the output is identical on every run.

learning

  • splitting a grid into column zones, one per letter;
  • an if / else if chain that dispatches on the column;
  • a nested test inside each zone for that letter's own shape;
  • diagonals written as row + col and col − row;
  • one cell width, two characters, for both the star and the blank;
  • what a chain with no final else leaves behind.

behaviour

Two println calls print the banner, using \n escapes inside the strings. Then the double loop prints five rows, with a newline after each. A final bare println() closes the output with one blank line.

No prompt appears, because no input is requested.

structure the source labels its own partitions

// complete grid → the two loops together // inside n x (n*3) → where a cell sits: n rows by 3n columns // zone - E / K / D → which letter owns this column // printing E / K / D → which condition makes a star

The comments divide the body into four levels of decision: the grid, the position inside it, the owning zone, and the shape test for that zone. Reading the file top to bottom gives you those levels in order — which is also how this page is organised.

A note on the notation: the source compares outerColE < 5-style bounds against the number 5, while the comment calls the width n. In a general version n would be a variable; here n is the literal 5 wherever the code needs it, and allowedCols is the only place the arithmetic is written as 5 * 3 + 2.

02 Problem statement

The grid, stated without the code

Five rows. Seventeen columns, of which three blocks of five carry the letters and two single columns sit between them. Every cell is printed as two characters — either a star and a space, or two spaces — so all rows share one width.

03 Core logic & approach

        
Two levels of decision, four branches

        
The loops never mention a letter. All of the drawing lives in one chain of conditions — the first question asks which zone owns the column, the second asks which cells of that zone are stars.

Why the K needs arithmetic

          
The E and the D are made of lines that run along the grid: r == 1 is a whole row, c == 13 is a whole column. One coordinate is enough to describe them.

          
The K's arms are diagonal, and no row or column test can describe a diagonal. The fix is to combine both coordinates so that the sum, or the difference, stays fixed:

          
    
            
  • r + c is constant along a line that moves down and left — the upper arm;
    • 
            
  • c − r is constant along a line that moves down and right — the lower arm;
    • 
            
  • c == 7 is the vertical stem those arms lean on.

Solving the two equations together gives r = 3, c = 8, the point where the arms meet, which is the middle row.

        

      

    

  


  
  

    

      

        
04 Key Java concepts

        
What the file demonstrates

        
Nine ideas carry this drawing programme. Each card states what the concept does in this file, why it is there, and what to keep.

      


      

        

          
column zones

          
The first test is outerColE <= 5. That one question — which letter owns this column — is what allows three different shapes to share a single pair of loops.

          
Why: without zones, each letter's rows would need column guards repeated inside them. Keep: partition the grid first, then draw inside each partition.

        


        

          
if / else if chain

          
Four branches, tested in order, mutually exclusive. A column that matches the first branch never reaches the second.

          
Why: a column can only belong to one letter. Keep: an exclusive chain also documents the partition — reading it top to bottom reads the grid left to right.

        


        

          
nested if

          
Inside each zone a second test decides star or blank. The outer chain answers "which letter"; the inner test answers "which cell of that letter".

          
Why: two different questions need two levels. Keep: each level should answer a strictly different question — otherwise one of them is redundant.

        


        

          
diagonal equations

          
outerRowE + outerColE == 11 and outerColE - outerRowE == 5 draw the K's arms. A constant sum is a down-left line; a constant difference is a down-right line.

          
Why: a row-major loop cannot step diagonally, but it can recognise a diagonal. Keep: these two families cover every diagonal in grid work.

        


        

          
uniform cell width

          
Both alternatives are two characters: "* " and "  ". Because the widths agree, every row is the same length and the letters stay aligned.

          
Why: mixing a one-character blank with a two-character star would shear the rows apart. Keep: decide the cell width once, and use it on both sides of every if.

        


        

          
literals as size

          
The number 5 appears in the banner text, in 5 * 3 + 2, in the row bound <= 5, in 5 / 2 + 1 and twice more in the E and D row tests. The values 11, 12, 13 and 17 encode positions.

          
Why: a fixed drawing is quick to write with literals. Keep: every literal is a promise that the size will never change.

        


        

          
escape sequences

          
One statement carries four lines: println("Here's My …\n Name : …\nInitials : E K D\n"). The \n characters break the string, and println adds a newline of its own at the end.

          
Why: fewer statements for one block of text. Keep: an escape inside a string and a newline written by println are two separate things.

        


        

          
integer division

          
5 / 2 + 1 evaluates to 3: division truncates before the addition. That is exactly the middle row of a five-row letter, and it is also the reason the E's middle bar is where it is.

          
Why: a middle row must be an integer index. Keep: for an even height this expression rounds down, so the "middle" sits one row above centre.

        


        

          
no final else

          
The chain ends at the D branch. A column that matches none of the four falls out of the if statement without printing anything at all — not even a space.

          
Why: the ranges were written as < 12 and > 12, which leaves 12 out. Keep: a closing else would have turned a silent hole into a visible, fixable one.

Limitations in this implementation

          
    
            
  • One column belongs to nobody. The chain covers ≤ 5, = 6, 7–11 and 13–17. Column 12 falls between < 12 and > 12, so it emits zero characters where every other column emits two. It is invisible today only because column 11 is blank on all five rows.
    • 
            
  • The size is written six times. 5 appears in the banner text, in 5 * 3 + 2, in the row bound, in 5 / 2 + 1 and twice in the letter tests. Changing the size means finding all of them, and the K's constants would need recomputing as well.
    • 
            
  • The K is anchored to the grid, not to itself. r + c == 11 and c − r == 5 describe this exact placement. Move the K one column and both arms shift; make the grid taller and the lower arm disappears past row 5.
    • 
            
  • No closing else. The chain stops at the D, so anything outside every range prints nothing rather than a space. That is what makes column 12 silent.
    • 
            
  • The banner is inside the drawing code. The name and initials are string literals in main, alongside the loops, so the file is a personal poster rather than a reusable shape.
    • 
            
  • The D has no corner treatment. It is a rectangle: two rows and two columns. Consistent, but not the rounded block letter a printed signature would use.
    • 
            
  • Nothing is a function of anything. The programme takes no argument and exposes no method, so the only way to produce a different signature is to edit and recompile.
    • 
          

        


        

          
Correctness, stated carefully

          
As a drawing: correct. For the fixed 5 × 17 grid the programme produces a readable E, K and D. Each row is 32 characters, the three letters are separated and vertically aligned, and the K's arms meet exactly on the middle row. The loops terminate after exactly 85 cell decisions.

          
As a pattern programme: hard-coded. The shape is right for one size and one placement. The E and D would survive a taller grid — their tests mention only rows 1, 5, the middle and the letters' own columns — but the K would not, because its two constants encode a five-row letter. That asymmetry is worth seeing: one file, some portable conditions and some frozen ones.

          
The missing branch is a defect, not a style choice. A cell that prints nothing shifts everything to its right by two characters, whereas a cell that prints two spaces does not. The output looks right because of an unrelated accident in the K's shape, not because the spacing was designed.

09 Time & space complexity

        
A fixed amount of work, by construction

        
Seventeen columns are tested on each of five rows, so the loop body runs exactly 85 times. Formally the shape is O(rows × cols); in practice the answer never changes.

      


      

        

          
Time — Θ(1) here, O(R × C) in general

          
The body runs 5 × 17 = 85 times. Each pass evaluates at most four zone conditions and, once inside a zone, up to four cell conditions. That is a constant amount of work per cell, so the total cost is proportional to the number of cells.

          
Output is 160 characters of grid plus the banner. Both the work and the output are fixed, which makes the programme Θ(1) with respect to everything — it has no inputs.

Roughly half the cells are stars. Of the 42 blanks, 37 print two spaces and 5 print nothing at all.

        


        

          
Space — Θ(1)

          
Two loop counters and one int for allowedCols, plus whatever System.out buffers internally. No array holds the grid, because each cell is decided, printed and forgotten in the same pass.

          
A version that stored the grid in a char[][] would need O(rows × cols) space for no gain here — there is nothing to revisit once a row has been printed.

          
If the size were a variable

          
Let the letter height be n and derive everything from it: the grid becomes n rows by 3n + 2 columns, the middle row becomes n / 2 + 1, and the K's constants become expressions of n and of the K's own start column. The programme then costs O(n²) time and Θ(1) space.

The trade in this file is simplicity against generality: fixed literals make the code short and the output certain, at the cost of never being able to draw anything else.

        

      

    

  


  
  

    

      

        
10 Takeaways & future connections

        
What this drawing teaches

      


      

        

          
lesson partition before you draw

          
Assign every column to an owner first, then write each letter's own condition inside its block. The loops stay untouched no matter how many letters are added; only the chain grows a branch.

          
The proof is in this file: three shapes, one pair of loops.

        


        

          
discipline make the ranges tile

          
Write the cover as a closed list before writing any code — 1–5, 6, 7–11, 12, 13–17 — and check that consecutive ranges share a boundary rather than leaving a gap between them.

          
Here the boundaries were written as < 12 and > 12, so 12 belonged to neither.

        


        

          
habit end the chain

          
A final else that prints a space costs one line and converts a silent hole into something visible on the first run.

          
Silence is the hardest output to notice, because the programme still looks like it finished.

        

      


      

        

          
Check your understanding

          
Every row is 32 characters, yet the grid has 17 columns of two characters each. Where did the missing two go, and why does the output still look evenly spaced?

          
          
Column 12 has no branch, so it prints zero characters instead of two — 34 − 2 = 32. The spacing survives because column 11, the K's last column, is blank on all five rows: the widest the K ever gets is column 10, so column 11 always contributes "  ". The gap between the K and the D is therefore column 11's two spaces plus column 12's zero, which coincidentally equals the two spaces of column 6. The layout is right by accident. It would become visible the moment the K widened — if the diagonals were changed to meet at column 9, the middle row would put a star in column 11 and the D would sit flush against it.

        


        

          
One more

          
The K uses both r + c == 11 and c − r == 5. Why does the first one print nothing on row 5, and what would the constant have to be to fix it?

          
          
On row 5 the equation gives c = 11 − 5 = 6, which is the gap column between the E and the K — outside the 7–11 zone, so the branch never gets that far and no star is printed. That is not a bug: the upper arm has already ended. Its last distinct cell is the meeting point at row 3, column 8 — on row 4 the same equation lands on column 7, which is the stem that is already being printed. Below the meeting point the lower arm takes over. If you wanted a K with arms that both span the full height, the upper arm would need a different constant — one that reaches row 5 at column 10, which is r + c == 15. That would also move the meeting point, so the two arms would stop crossing at the middle row. The pair 11 and 5 is what makes them meet exactly at row 3.

        

      


      

        
later

        
The next version of this idea is the same programme with the size named once and every boundary derived from it: zones as expressions, the middle row as n / 2 + 1, and both K constants written in terms of the stem column and that middle row. Then the signature could be drawn at any height without touching a literal.

        
Past that, the same two ideas recur everywhere. Deciding a cell from its coordinates is how sprites, chessboards and image tiles are addressed, and recognising a shape by an arithmetic relation between indices is the beginning of matrix work — testing whether a cell lies on a diagonal, inside a triangle, or in a band.

Everything the programme knows is in its literals, which is why the output is the same on every run.

Where this leads

        
The signature draws correctly. The open question is what the same conditions would look like if the size stopped being a literal — and that question has a precise, small answer.

      


      

        

          
Name the size, then derive everything

          
The file already contains the rule it needs: 5 * 3 + 2 is a size formula written as a constant. The step is to name the height, then express every boundary and both diagonal constants from it.

          
int n   = 5;              // letter height
int mid = n / 2 + 1;      // middle row
int e0  = 1,        e1 = n;        // E
int k0  = n + 2,    k1 = 2*n + 1;  // K
int d0  = 2*n + 3,  d1 = 3*n + 2;  // D
int allowedCols = 3 * n + 2;

// K arms, from the stem and the middle row
boolean upper = (r + c) == (k0 + mid + 1);
boolean lower = (c - r) == (k0 - mid + 1);

          
The loops do not change. The chain keeps its shape. What changes is that every 5, 11, 12, 13 and 17 becomes a name, and the K stops being tied to one grid.

          
Not assumed. Whether this is the next programme you write is your call — the page stops at the question.

        

        

          
What carries forward from this file

          
    
            
  • Zones first. Decide the column partition, check it covers the grid, and only then write the letters.
    • 
            
  • Close the chain. A final else that prints a space makes an unclaimed column visible instead of silent.
    • 
            
  • Diagonals are equations. A constant r + c and a constant c − r — two families, four edges.
    • 
            
  • One cell width. Both branches of every cell test must print the same number of characters.
    • 
            
  • Truncation is a tool. 5 / 2 + 1 is a middle row only for odd heights; for even ones it lands one row low.
    • 
            
  • Keep the banner separate. A name is not part of a shape; mixing them makes both harder to reuse.
